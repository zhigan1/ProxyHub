## 2. 虚拟分组模型（auto-flash 等）

**概念**：在真实模型之上加一层虚拟模型。客户端请求 `model: "auto-flash"`，网关按优先级从组内挑第一个「未熔断」的候选执行，失败自动换下一个。

**分组不进代码，进 config.json**：

```jsonc
{
  "groups": {
    "auto-flash": {
      "match": ["*-flash"],                       // glob，对"当前生效模型表"求匹配
      "prefer": ["codebuddy", "traecn", "qoder"], // 平台优先级排序
      "description": "速度优先，自动在全部 flash 间切换"
    },
    "auto-pro":  { "match": ["*-pro", "*-max"], "prefer": ["codebuddy"] },
    "auto-glm":  { "match": ["*glm*"] },
    "auto":      { "match": ["*"] }
  }
}
```

要点：

- `match` 作用于 **Registry 当前生效模型表**（动态拉取优先的那张表）→ 平台上线了新的 flash 模型，分组自动收录，零维护。
- 分组自身出现在 `GET /v1/models`（`owned_by: "proxyhub"`），任何 OpenAI 客户端可直接选用。
- 组数不限，增删改全部走配置/管理页。
- 组内排序 = **账号轮次**：先跨平台把各平台第 1 账号全部试完（轮内按 `prefer` 平台序，未列出的平台按注册顺序殿后，Qoder 注册最后、每轮殿后），全部失败才进入第 2 轮备用账号；同平台同账号内模型按名字典序（稳定、可预测）。

**Registry 改动**：新增 `GroupRegistry`（解析分组、展开候选链）；`ResolveModel` 先查分组再查真实模型；`ListModels` 追加虚拟模型。

**动态模型发现与生效模型表**：

各适配器启动时后台异步从本地数据源拉取当前可用模型；成功时覆盖内置静态基线，失败、被锁或格式变动时返回 `null` 并自动回退静态基线，不阻塞服务启动：
- **CodeBuddy**：按优先级依次读取本地服务端下发缓存（`~/.codebuddy/local_storage/entry_*.info`）、安装配置清单（`product.json` / `product.internal.json`）及 CLI 探测（`codebuddy --help`）。
- **Qoder**：使用本机 CLI（`qoderclicn --list-models`）。
- **TraeCN 与 TraeWork**：只读各自 `StorageFile` 同目录 `state.vscdb` 的 `ItemTable` 中以 `AI.agent.modeListMap` 与 `AI.agent.model.model_list_map` 结尾的两个服务端模型缓存键，解析服务端下发 JSON 提取聊天模型列表。
  - **零网络与零凭据**：纯本地只读解析，不联网发起上游请求，不读取或解密任何用户凭据；
  - **零第三方依赖**：通过 Windows 内置 `winsqlite3.dll` P/Invoke 只读打开（带 300ms busy timeout），共享模式容忍桌面端占用，零 NuGet 依赖；
  - **安全降级**：缓存缺失、被锁、损坏或格式变动时返回 `null` 并自动回退静态基线；
  - **多账号场景限制**：当前动态发现仅读取默认 profile（即默认 `storage.json` 所在目录）的 `state.vscdb`。

## 3. 自动熔断 + 故障转移

### 3.1 熔断器（CircuitBreaker）

- **粒度**：`{适配器}:{账号}:{模型}`，三者任一变化都是独立熔断节点。
- **状态机**：`Closed` →（连续失败 N 次，默认 2）→ `Open`（冷却 T 秒，默认 60）→ `Half-Open`（放行 1 个探测请求，成功回 Closed，失败续 Open）。
- **计入失败的错误**（可重试类）：网络异常、超时、5xx、429、401（先自动刷新一次凭据，再失败才计）。
- **不计入失败的错误**：400/422 等客户端参数错误——换个模型重试也治不好，直接透传给调用方。
- 参数全部可配：

```jsonc
{
  "circuitBreaker": { "failureThreshold": 2, "cooldownSeconds": 60, "halfOpenProbe": true }
}
```

### 3.2 故障转移执行器（FailoverExecutor）

请求 `auto-flash` → 展开候选链：

```
auto-flash
├─ 第 1 轮（各平台第 1 账号，轮内按 prefer 平台序）
│   ├─ codebuddy 账号A
│   │   ├─ codebuddy-deepseek-v4.1-flash
│   │   └─ codebuddy-glm-5.3-flash        （同账号内模型按字典序）
│   ├─ traecn 账号A
│   │   └─ traecn-glm-5.3-flash
│   └─ qoder 账号A                        （Qoder 每轮殿后）
│       └─ ...
└─ 第 2 轮（备用账号，仅第 1 轮全部失败后进入）
    ├─ codebuddy 账号B → traecn 账号B → ...
    └─ ...
```

切换语义：**先跨平台把各平台第 1 账号的候选全部试完 → 全部失败才动用第 2 轮备用账号 → 整链熔断/失败 → 报错并附熔断详情**。候选链逐节跳过处于 Open 状态的节点。

### 3.3 流式的关键约束与对策

SSE 一旦向客户端写出第一个字节，HTTP 状态码已提交，**无法再换源**。对策：

- **首 chunk 前缓冲**：网关先对上游发请求，等到第一个 chunk 到达才向客户端写响应头。在此之前失败 → 熔断该节点 → 换下一候选重发，客户端无感知。
- 首 chunk 写出后再断流 → 无法透明重试，补一条 error chunk + `[DONE]` 收尾（行业标准做法，Cherry Studio/Cline 均能正常显示）。
- 非流式请求无此约束，天然支持整链重试。
- 发生切换时在响应头标注 `X-ProxyHub-Failover: codebuddy-deepseek-v4.1-flash@A → traecn-glm-5.3-flash@A`，便于排查（可在配置中关闭）。

## 4. 多账号发现

**IAdapter 接口扩展**（不破坏现有方法，新增一个）：

```csharp
public sealed record AccountCredential(string AccountId, string Label, AuthInfo Auth);

public interface IAdapter
{
    // …现有成员不变…
    /// <summary>枚举本机可发现的全部账号；至少返回一个，发现失败返回空并记录原因。</summary>
    Task<IReadOnlyList<AccountCredential>> DiscoverAccountsAsync(CancellationToken ct = default);
}
```

各平台发现策略：

| 平台 | 自动发现 | 手工追加（config.json） |
| --- | --- | --- |
| CodeBuddy | 扫描 `%LOCALAPPDATA%\CodeBuddyExtension\Data\Public\auth\*.info` **全部**文件（当前写死 2 个文件名，改为目录扫描），每个文件 = 一个账号 | 指定额外 auth 文件路径 |
| TraeCN / TraeWork | 扫描 `%APPDATA%` 下 `Trae CN*`、`Trae Work*` 多版本/多实例目录的 `storage.json` | 指定额外 storage.json 路径 |
| Qoder | CLI 配置目录 | 直接粘贴 token |

```jsonc
{
  "accounts": {
    "codebuddy": [ { "label": "小号", "authFile": "D:\\secrets\\cb-2.info" } ],
    "traecn":    [ { "label": "账号B", "storageFile": "C:\\…\\storage.json" } ]
  }
}
```

**风险提示**（写入 README）：同平台多账号高频并发可能触发平台风控，默认每个适配器仍只用第一个健康账号，仅在熔断/切换时动用后备账号；负载均衡模式启用前请自行评估。

## 5. 配置中心 v2 + 热更新

把现存写死项全部搬进 config.json：分组、熔断参数、手工账号、切换头开关，加上已有的端口/key/超时/适配器开关。

- **热更新**：`FileSystemWatcher` 监听 config.json，300ms 防抖后重载。分组、熔断参数、账号列表即时生效（重建 GroupRegistry、调整 CircuitBreaker 参数，不清空既有熔断状态）。
- 端口、适配器开关属结构性变更：热更新不生效，管理页标注「需重启」。
- 管理页保存 = 写回 config.json → 自然触发热更新，单一事实来源。

## 6. 可视化页面 /admin

**形态**：自包含单 HTML 页（无 CDN、无构建步骤，已以嵌入资源 `EmbeddedResource`（LogicalName `ProxyHub.wwwroot.admin.html`）随程序集交付，运行时无需磁盘 `wwwroot` 目录），原生 JS + fetch。首次打开输入 proxy key（存 sessionStorage），与现有 API 同一套鉴权。默认端口为 8265。

**五个板块（已全部交付）**：

1. **总览**：适配器就绪状态、今日请求/token、每日用量趋势（canvas 手绘，零依赖）、熔断中节点高亮。
2. **模型矩阵**：按家族分组的模型能力矩阵 + 行级可用账号数与熔断（Open / Half-Open）状态统计（`GET /admin/api/models/matrix`）。
3. **分组管理**：分组 CRUD（match 模式、平台排序、说明）+ 编辑弹窗内草稿实时预览（约 200ms 防抖提交 `POST /admin/api/groups/preview`，纯内存展开不落盘，校验错误内联展示）。
4. **账号管理**：账号列表（标签、来源、健康/熔断状态）、表单化手工添加账号（CodeBuddy=`authFile`、Trae 系=`storageFile`、Qoder=`pat`）、重新扫描本机账号、一键复位全部熔断与单节点熔断复位。
5. **配置编辑**：结构化 groups / accounts 编辑 + 原始 JSON 诊断视图（PAT 自动脱敏为 `******`，且不回填输入框），保存即热生效；结构性项标注「需重启」。

**管理 API**（全部要求 proxy key，以当前运行事实为准）：

```
GET    /admin                        单页 HTML（程序集嵌入资源交付）
GET    /admin/api/overview           状态 + 用量汇总 + 熔断快照
GET    /admin/api/groups             分组列表（含候选链展开预览）
POST   /admin/api/groups/preview     分组草稿纯内存展开预览（不写 config.json）
GET    /admin/api/models/matrix      模型健康矩阵（家族 × 平台：可用账号数 + 熔断状态）
PUT    /admin/api/groups/{name}      创建/更新分组
DELETE /admin/api/groups/{name}      删除分组
GET    /admin/api/accounts           账号 + 熔断状态
POST   /admin/api/accounts/refresh   重新扫描本机账号
GET    /admin/api/breakers           熔断器快照（key / 状态 / 连续失败数）
POST   /admin/api/breakers/reset     复位熔断（body 可选 key 复位单节点，缺省复位全部）
GET    /admin/api/config             当前配置
PUT    /admin/api/config             保存配置（写文件 + 顶层键合并热更新）
```

## 7. 负载均衡方案（多人使用 · 本期只写方案）

> **范围界限**：L1–L3 负载均衡均**未实现**，本节仅为演进方案，当前代码不含任何均衡策略。

分三层演进，按需取用：

**L1 单机多账号均衡**（下一迭代可实现）
- 候选链从「固定顺序」改为「加权选择」：健康节点中按 **least-inflight**（在途请求最少）+ 延迟 EWMA 选账号。
- 每账号速率护栏（每分钟请求上限），避免触发平台风控。
- 改动面小：FailoverExecutor 的候选排序策略从 `OrderedStrategy` 换成 `LeastInflightStrategy`，配置切换。

**L2 多用户治理**
- proxy key 升级为多 key（每用户一把），UsageTracker 按 key 记账，管理页出「按用户」用量视图。
- 每用户 token bucket 限流。

**L3 水平扩展**（团队级）
- 网关无状态化：熔断状态、inflight 计数外置 Redis，多实例共享。
- 凭据从「扫本机」改为集中密钥保管（Vault / 云 KMS），账号池管理员统一录入。
- 前置 nginx / 云 LB 分发实例，实例内仍走 L1 账号均衡。
